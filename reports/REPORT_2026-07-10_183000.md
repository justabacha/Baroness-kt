## Summary
The Dashboard feature implements a basic caching mechanism for daily vibes and images but falls short of a true "offline-first" experience. Significant issues include a blocking loading spinner even when cached data is available, case-sensitive image loading that breaks on `.JPG` extensions, and a lack of background sync to verify cache freshness. The overall health is "Fair", with risks related to UX frustration and data inconsistency if remote source URLs change without updating local filenames.

---

## Critical Issues (Fix Immediately)

### Issue #1: Image Loading Case Sensitivity (Broken URL Logic)
- **File(s):** `QuoteRepository.kt` (lines 78-79, 137), `QuoteCard.kt` (lines 75-76)
- **Problem:** The app hardcodes `.jpg` extension in `downloadImage` and `getExistingImage` (lines 78, 137). If a remote URL (e.g., from `SignatureLoops.kt`) ends in `.JPG`, the download might succeed, but the app stores it with `.jpg` locally or fails to find it because of literal string comparison. Furthermore, the `imageUrl` check in `QuoteCard.kt` only detects local files if they start with `/` or contain `/data/user/`, which might fail if path separators or relative paths are inconsistent.
- **Severity:** 🔴 Critical
- **Suggested Fix:** Normalize file extensions during download and checking. Use `String.endsWith(".jpg", ignoreCase = true)` and ensure local filenames are derived consistently.
- **Behaviour Impact:** Major (Images fail to load)
- **Offline Impact:** Breaks image display for any URL not matching the hardcoded lowercase extension.

### Issue #2: Loading Spinner on Every Open (Offline-First Violation)
- **File(s):** `DashboardViewModel.kt` (lines 62, 85), `DashboardScreen.kt` (lines 106-111)
- **Problem:** `_isInitialLoading` is set to `true` by default and only set to `false` at the end of `loadInitialData`. Because `getTodayQuote` (line 77) is a `suspend` function called inside `loadInitialData`, the UI blocks with a spinner while the repository performs its disk I/O check, even if data is cached.
- **Severity:** 🔴 Critical
- **Suggested Fix:** Check for cache presence immediately and set `isInitialLoading` to `false` if data exists. Load in the background while displaying cached content.
- **Behaviour Impact:** Major (Poor UX/Flicker)
- **Offline Impact:** Violates the principle of "App must function fully without network" by showing a blocking UI state.

## Medium Issues (Fix Next)

### Issue #3: Lack of Cache Validation (Background Sync)
- **File(s):** `QuoteRepository.kt` (lines 38-40)
- **Severity:** 🟡 Medium
- **Problem:** The repository only checks if the `cachedDate` matches today. It never checks if the remote URL in `SignatureLoops.kt` has changed while the date remains the same. If an image is updated on the server under the same URL or if a bug was fixed in the source list, the app remains stuck with stale cached bytes.
- **Suggested Fix:** Implement a background "head" check or ETag comparison, or simply re-download in the background if a network is available while showing the cached version.
- **Behaviour Impact:** Minor (Stale content)
- **Offline Impact:** Content remains static and potentially incorrect despite network availability.

### Issue #4: Weather Cache Expiration Logic
- **File(s):** `DashboardViewModel.kt` (lines 89-91)
- **Severity:** 🟡 Medium
- **Problem:** Weather is refreshed only if the cache is >10 minutes old. However, `refreshWeatherInBackground` (line 120) is called at the very end of `loadInitialData`. If the user is offline, the weather "Loading..." text persists even if old data exists because `_weather.value` is only set after the `refreshWeatherInBackground` call (which might time out or fail).
- **Suggested Fix:** Ensure `_weather.value` is populated from cache *before* attempting the background refresh.

## Architecture Recommendations
1. **Source of Truth:** The `VibeManager.getVibeOfTheDay()` should be treated as a suggestion, while the `QuoteRepository` should be the absolute source of truth for the Dashboard UI state.
2. **Resource Normalization:** Implement a utility to sanitize URLs into local filenames (e.g., MD5 hash of URL) to avoid extension mismatch issues.
3. **Optimistic UI:** Always show cached data immediately. Use a non-blocking indicator (like a small sync icon) for background refreshes instead of a full-screen spinner.
